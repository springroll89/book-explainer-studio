# 名称与译名同步

人物稳定 ID 和原文名用于身份核对；`analysis/characters.yaml` 是本书现用名及旧称映射的唯一来源。名称变化属于实体资料修正，不是普通语气偏好。人物 ID 与原文名不变，只按证据修订 `spoken_name`、必要时修订 `name_zh`。

## 先消歧，再变更

- 用户明确指定更名时核对人物 ID、原文名、适用书目与上下文；同姓、简称歧义、原文名不同或新人物未登记时先查原文，无法确定就询问。明确更名指令无需重复请求许可，但不能扩大到其他书目。
- 改稿差异、批注和口头说明中的名称都要看；`name_review_candidates` 只是提示，不自动证明人物身份或授权范围。
- 不因相似读音/汉字合并人物。逐字引文保持原样；若引文与现用名冲突，单独标注并复核，不做全局忽略。

## 变更步骤

1. 运行 `./run.sh name-change <项目> --entity <人物ID> --name <新口播名> --output <变更单路径>` 生成影响清单；命令只列清单，不自动替换。核对文件位置、出现次数与摘要。
2. 在书目私有目录 `name_changes/<编号>/` 保存变更单及目标文件原样副本。执行前复核摘要；文件已变化时重新读取并合并，不覆盖较新的人工修改。
3. 更新人物表的现用名和更正依据；旧称标为 `deprecated`，直接映射到最新现用名，避免旧称链。示意：

   ```yaml
   aliases_zh:
     - text: 之前的中文简称
       replacement: 当前中文简称
       status: deprecated
   ```

4. 只更正活动资料中的实体名称：分析、人物/线索说明、计划、当前稿件、标题、封面文字、制作说明和派生文字。逐字直接引文保留原样并单独复核；不得改写案情或全库盲替换。
5. 另存新版稿，重新核查来源标记、上下文、句子 ID 与下游依赖；运行 `./run.sh next <项目>` 推导状态，不手改状态文件。受影响集数按现有流程标记需复核，旧审校结论不能自动沿用。
6. 从新版稿重生成口播、字幕、阅读页等文字产物。音频、视频及已发布内容列为待重新生成/处理，不能靠改名声称同步完成。
7. 运行 `names-check`、新版稿 `lint` / `quotes` 和受影响审校；报告原称→现称、对应人物、已改文件及次数、历史保留范围和剩余媒体待办。

检查只覆盖工具识别的活动文本，不验证音视频里的真实读音；零旧称命中也不证明人物身份判断正确。原文、旧稿、审校和差异记录保持原样，历史中的旧称按人物 ID 与旧称表解释。陌生音译、未登记别称仍须回原文核对。
