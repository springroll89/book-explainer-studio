# visual-development

视觉开发是口播之后的视频制作流程。主会话先运行 `./run.sh next <项目路径>`；只允许写本集目录的任务卡子会话改用 `python -m bookflow next <项目路径> --read-only --json` 预检，不刷新共享进度。再读取派生的 `state.json`、`analysis/characters.yaml`、当前分集计划和工作流文档；不要把聊天中的临时印象当作人物资料。

## 固定制作顺序

1. **先完成带音效的声音时间表**：豆包 2.0 生成口播后，先按声音清单加入豆包 1.0 音效并完成试听、停顿和混音验收，再以最终“口播＋音效”文件生成逐字、逐句时间表。画面切割只能使用这份实际时间表，不能只看纯口播时长。
2. **判定哪些段落需要画面**：按剧情信息变化、场景切换、人物关系、关键动作、线索揭示和结尾悬念筛选画面段落。每一段都必须对应一个语义完整的表达；不能为了凑频率切断同一件事。
3. **自动生成三种画风候选**：根据书籍题材、叙事气质和画面段落，先产出三种差异明确的画风小样，供用户比较确认。候选要说明色彩、线条、材质、人物表现和适用风险；用户确认前均为 preview，不得写成已定稿。
4. **整部书统一人物定妆**：画风确认后，一次性为整部书需要出镜的人物建立参考图，不区分主要人物和次要人物。每人绑定稳定人物 ID；脸型、基础发色、年龄感和体型是身份锚点。眼色、服装、光线和构图若无原文依据，标为美术设定。定妆册完成后必须做人物并排可辨识度检查：相邻或可能同框的人物，脸型轮廓、发型/发色、年龄感、体型、肤色/地域特征和标志性服装或配件中，至少要有两到三项形成清晰差异；不能让不同角色只靠服装或剧情语境才能勉强区分。若女警探与实际凶手、多个男主等人物在并排缩略图中容易认错，必须先重做定妆参考，再进入剧情生图。
5. **建立状态版本**：回忆年龄、染发、妆容、伤势、季节服装等变化另存状态版本，不能临场换脸。人物参考图、剧情场景和书籍介绍图分开管理；画面不能提前泄露凶手、线索或人物身份。
6. **制作分镜**：定妆完成后，再按语义完整的画面段落制作分镜清单。每个镜头绑定人物 ID、参考图、场景、动作、景别、唯一画面资产、实际时间和口播锚点，并标明哪些内容是原文事实、哪些是美术推断。
7. **先做第一集视频样片**：按当前混音的最终时间表写 `production/storyboard.yaml`（每镜 start/end 与 image），在会话内逐镜生成图片，再运行 `./run.sh produce <项目> epNN`：它核验分镜、图片与节奏后登记分镜/画面阶段，并用本地 FFmpeg 渲染；预览必须有可见字幕。用户“拍板样片”后，剩余集数按不重叠的批次继续制作。
8. **逐层验收**：检查画风、人物身份、场景连续性、剧透边界、唯一画面、字幕和音画同步。已生成不等于已保持一致；用户确认前保留候选版本和待改项。

交付至少包括：三种画风候选、全季人物定妆册、需要做图的段落清单、分镜表、第一集带字幕样片、字幕源文件与审计记录、渲染配置及导出文件、版本清单和剩余验收项。图片提示词放在项目视觉目录，不写进纯口播稿。

### 人物定妆画廊验收

- 每张人物卡必须以稳定人物 ID 显示并明确绑定定妆图片路径和版本；不能依赖数组顺序、文件名猜测或相邻卡片推断人物对应关系。用人物表核对卡片 ID、姓名和角色数，逐项检查映射目标存在且图片可加载。
- 分开验收“人物绑定”和“页面呈现”：前者检查 ID—姓名—图片—版本是否一致；后者检查 HTML/CSS、图片裁切、卡片排版、窄屏溢出和放大查看等交互，并在实际浏览器中查看页面。资源路径全部存在不等于布局正常，页面布局异常也不自动代表人物映射错误。
- 若绑定检查通过但页面排版有问题，可继续按稳定 ID 定位人物并记录视觉反馈，同时修复并复查页面；在浏览器呈现复核前，不得报告画廊整体验收完成。

## 画面节奏硬规则

分镜完成后必须补齐 `segment_role`、`shot_kind`、`framing`、`asset_id`、`time_est/time_actual`、`fact_level` 和 `evidence`，并运行 `./run.sh pacing check`。

- **8–15 秒是不可越过的硬边界，语义切分须在边界内完成**：每个画面切片必须至少 8 秒、至多 15 秒；只能在这个区间内机动选择停留时长，不得用短于 8 秒或长于 15 秒的镜头兜底。这个范围来自第一本书的制作探索，是观众观看舒适度的规则，不得自行放宽。切片同时须对应完整、可理解的内容单元；不得仅按句号、时间点或字数机械切开，更不能截断动作、因果、连续对话或信息揭示。一个语义单元不足 8 秒时，应与相邻且语义相连的内容合并；一个语义单元超过 15 秒时，应在其自然的子动作、因果转折、对话轮次或信息揭示点拆成连续镜头，使每段各自落在 8–15 秒内，同时让事件和口播连贯推进。若暂时找不到同时满足语义连贯与时长边界的切法，标记为待解决并重新设计分镜，不得突破 8 秒或 15 秒边界，也不得静默输出。
- **开场强变化不等于切片次数**：开场 30 秒至少 6 次强变化，统计镜头切换与镜头内部明确设计的视觉变化。镜头内变化可通过焦点、构图、视线、景别或有依据的画面运动实现，并须在分镜标注实际时点和具体变化；不得把同一变化重复计数，也不得为了凑次数突破 8–15 秒或语义边界。`pacing check` 应合计镜头边界变化与有效的 `strong_change_beats`。
- **一切片一张独立剧情图（硬规则）**：每个 8–15 秒画面段落必须绑定一个只属于该切片的唯一剧情画面资产。相同文件、相同构图、同一画面的重复裁切、只改色调或只改轻微运动，都视为复用；分镜审计必须确认整集 `asset_id`、文件路径、构图指纹均无重复。人物定妆照只用于身份参考，不能代替切片画面。画面数量由实际语义切割决定。
- **跨集画面隔离（硬规则）**：除非用户明确批准跨集复用，每一集的剧情画面必须根据该集切好的语义重新生成；第一集的剧情图、旧分镜和旧视频不得作为后续集的默认画面来源。人物定妆照只能作为身份参考，不能把第一集剧情图冒充为新一集画面。若确有跨集复用，必须在分镜中写明批准来源、语义精确匹配理由和唯一使用位置。
- **人物身份必须结合上下文判断（硬规则）**：切片里的人物即使没有姓名，也不能因此视为新角色或随意套用某张定妆图。绑定人物 ID 前，必须联合阅读该语义段前后的完整句子、人物关系、动作承接和原文证据，判断代词、称谓、对话说话者及省略主语分别指谁；不得只看当前一句或离散时间码，也不得从相邻画面的构图反推身份。先记录“文本称呼/代词 → 上下文所指人物 → 稳定人物 ID → 状态版本”的对应依据，再生成提示词。若结合上下文和原文仍不能唯一确定，标记为身份未决，不猜测、不绑定固定脸，改用背影、手部、遮挡或不具名局部构图，并将待决点留在分镜审计中。
- **人物出镜隔离（硬规则）**：人物定妆参考必须从当前集该语义段的正文、前后文和人物表交叉确认，不能继承上一集旧分镜的 `character_refs`。生成前后逐项核对“画面人物—上下文所指对象—原文证据—定妆 ID—状态版本”一致；发现张冠李戴或无法解释的身份跳变时，停止该镜头生成并修正绑定。
- 画面段落数量以总时长÷8–15 秒估算；约 13 分钟通常约 51–95 幅，最终以语义完整和音画相关性为准。

## 音画相关性硬规则

画面首先解释口播，节奏其次。生成或选图前，必须把每段口播拆成可视化信息单元，并为镜头写明 `audio_anchor`、`visual_subject`、`visual_action`、`visual_place`、`visual_prop` 和 `cut_reason`。镜头至少要对应其中一个正在被口播推进的事实；只有泛场景、气氛或漂亮构图而看不出“谁在做什么”的图，不能替代人物行动镜头。

- 口播点名人物、介绍身份或描述行动时，优先切到该人物的定妆一致画面，并让姿态、视线或动作与台词一致；不能继续使用无人的环境图。
- 口播进入新地点、物件或线索时，画面必须在该句附近完成场景/物件切换；不能让上一场景跨过已经发生的剧情转折。
- 每个镜头在生成前做“听一句看一眼”检查：只听对应句子，观看者应能立刻说出画面在表现谁、在哪里、正在做什么。不能回答时，重写提示词或换图。
- 生成提示词必须显式带入稳定人物 ID 和对应定妆参考；不得用“中年男人”“一个女人”等泛化占位替代已知人物。人物不在画面中时，才使用与口播事实直接相关的物件或地点镜头。
- 分镜完成后，除 `pacing check` 外必须做音画相关性抽查：至少覆盖人物介绍、地点切换、关键动作、线索揭示和结尾悬念；相关性弱的镜头标为待重做，不得用镜头数量或画面美观度抵销。

## 静态图转场与镜头运动

- 静态图之间只使用一种统一、简单的平移转场（默认 FFmpeg `slideleft`，时长读取项目配置），不混用交叉淡化、推拉、炫光或其他花哨效果。
- 禁止使用“慢慢淡入”作为默认转场；它会拖慢 8–15 秒的画面节奏。转场时长保持短而一致，不能遮挡字幕、人物脸部和关键物件。
- 转场完成后必须抽查交界前、中、后三个实际画面，并检查整集画面资产 ID 是否零重复。

## 系列视频标题卡与字幕基线

- **标题卡默认模式是嵌入原有剧情画面**：若系列声音标识段有独立停顿，在该声音段内直接把本集标题卡叠加到该时间段原本的剧情画面上；上方为较大的“第 N 集”，中间用细分隔线，下方为分两行的本集集名。标题卡只使用已有声音停顿，不延长音频、不重复字幕，也不另插一段黑底或静帧视频。
- **独立插入片段不是常规方案**：只有在已经完成的成片缺少标题卡、且重新切分/重生图会破坏既有画面—口播对应关系时，才允许使用 `insert_segment` 作为一次性补救。该补救必须在元数据中写明 `mode: insert_segment`、原因、源视频版本、插入点和人工复核结果；新制作的集数默认一律使用 `overlay_on_original_plot_frame`。
- 每个有分集标题的 package 都必须有可核对的标题卡清单：集数、集名、声音 cue、时间范围、模式和音频版本。package 有标题但缺少 cue 或模式未声明时，制作前置检查必须阻断，不能静默导出无标题卡视频。
- 默认视觉参数以项目 `production/video_style_baseline_v1.yaml` 为准：集数 56 px 暖金色，集名 70 px 白色黑描边，居中排版；长集名按语义或视觉平衡换行。
- 字幕固定使用简体中文、保留最终稿标点、底部居中、白字黑描边；默认 PingFang SC、20 px、描边 2 px、底部安全边距 42 px。ASR 只负责时间对齐和差异审计，不能提供字幕正文。
- 音频或口播稿变更后，标题卡落点、字幕和视频必须从当前最终时间表重新生成；不得沿用旧版字幕或切点。

## 制作锁定与统一前置检查

- 进入生图或视频渲染前，建立 episode-local 制作清单，至少锁定：定稿 Draft 的 SHA256、package 标题、接受的音频版本、最终时间表、字幕版本、分镜版本、标题卡清单、8–15 秒节奏规则和“一切片一张独立剧情图”的唯一性规则。缺任一项不得进入下游。
- 用户试听并接受“口播＋音效”后，才把 `accepted_audio_version` 写入清单。之后任何口播、音效、停顿、混音或音频文件变更，都必须生成新版本并重新试听；旧字幕、切片、标题卡和视频不能只改文件名继续使用。
- 视频制作脚本按单集串行执行，默认不并行编码；各阶段输出机器审计，但 `preview_awaiting_human`、试听接受及四项确认仍保留真实人工状态，不由脚本代填。
- **并行批次的音色同步**：所有会话读取同一项目级 `production/voice_cast.yaml`，不在各自会话里凭记忆选音色，也不直接改共享表。批次清单记录 voice-cast revision 和 SHA-256；新增音色需求分别写进批次专属请求文件，由协调会话按稳定人物 ID 去重、取得用户提供的 voice ID、集中更新版本。各会话在开始 TTS 前必须读取同一锁定版本；版本不一致时暂停 TTS 并刷新清单。批次音频试听通过后，才能制作对应分镜；用户确认图片后才进入成片合成。

## 系列片头海报与文字层

- 系列片头海报先生成不含文字的 16:9 背景，再用本地确定性排版叠加文字；不要把需要准确显示的中文书名、德语原名或年份交给生图模型直接生成。
- 背景可参考实体书封面，并从整部剧情中选取少量可核实的核心意象；背景是氛围与识别元素，不得把尚未讲到的线索做成确定事实。
- 海报必须同时显示中文工作名和德语原名，标题文字要在缩小到实际播放尺寸后仍清楚可读。中文优先使用笔画均匀、字重足够的字体；避免细笔画书法字在暗背景中消失。
- 不用大块不透明或高对比圆角底板遮住剧情背景，避免“贴片”感。优先用高对比填充、轻微深色描边或偏移阴影解决可读性；若必须加衬底，应保持透明、克制，并检查是否破坏主体构图。
- 文字层修改从干净背景重新渲染，保留 `poster_vN.png` 与对应元数据 JSON；不要在旧文字层上反复叠字。元数据记录尺寸、字体、标题文本、背景来源和当前预览状态。
- 输出前用 `identify` 验证 3840×2160（或项目指定 4K 尺寸），并实际查看缩小预览，检查中文、德语、作者名没有缺字、细笔画消失、裁切或与关键剧情元素重叠。
