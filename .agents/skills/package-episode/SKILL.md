# package-episode

读取 [打包与真实验收](../../../docs/WORKFLOW.md#打包与真实验收)。

用户要求“全季文案一起修改”时，先按 `drafting.mode: full_season_review` 为每集运行 `edit copy`，再提供完整目录和合并阅读稿；保留各集原稿快照、独立编辑基线和来源索引。文字编辑包不要求 G2/G3/G4，不以 `export --preview` 的媒体闸门卡住文案交付。用户统一改稿之前，不把这些草稿称为已定稿，也不生成配音、画面或正式发布包。

打包前运行 `./run.sh names-check <项目路径>`。名称变更后从新版稿重新生成口播、字幕和展示文案；旧音频/视频不能因文字已改就标成已同步。详情见[名称同步参考](../import-feedback/references/name-consistency.md)。

预览运行 `./run.sh export <稿件路径> --preview --review <汇总路径>`。正式交付先确认本版审校、用户确认与账本依赖有效，再运行 `./run.sh export <定稿路径> --deliver --review <汇总路径>`；开发授权无需重复确认，但不能代替 G4。

补齐标题、封面文字、简介标签、字幕重点词和配音提示。实际打开产物，检查纯口播无内部标记、制作清单完整且时间码注明估算，质检摘要列出核心收获、来源、审校能力与剩余问题。

## 声音与时间表

声音规划与纯口播分离：口播和音效都直接走已配置的豆包 API，但使用不同模型。豆包 2.0 只接收 `voiceover.txt` 生成连续口播；豆包 1.0 负责音效、环境声、回声和可复用片头，提示词与落点写入独立的 `production/sound_cues.yaml`（历史 `sound_plan.yaml` 只作迁移依据）。两者共用同一份本地 API 配置，凭据只从环境变量或本机配置读取，不能写入稿件、Skill、日志或交付文案。ChatCut 只负责导入音频、剪辑、混音、字幕、画面和导出，不承担口播或音效生成。

每条声音必须有 `sound_class`、`function`、句子锚点、来源/制作依据、`gap_policy` 和状态。开场黄金 5 秒不放可辨认事件音；声音需有可辨声源和叙事用途，不能增加原文没有的事实。正式音频生成和绑定的服务状态、授权与验收规则见 [produce-audio](../produce-audio/SKILL.md)。

口播和人物音色以项目级 `production/voice_cast.yaml` 为唯一人工配置来源；人物用 `analysis/characters.yaml` 的稳定 ID。每集提交 TTS 前，批次清单须锁定该表的 revision 与 SHA-256，并核对生成任务的 `speaker`、`resource_id`、模型和采样率。旁白的 voice ID、resource ID、模型和采样率须与 `project.yaml` 一致；不一致时暂停并由协调会话统一修正。跨会话只读音色表；新增角色音色写到各自批次目录的独立请求文件，由协调会话去重、征询用户并更新共享表。主要说话人物必须有专属确认音色；次要人物可使用已确认的共用音色池。不得让两个会话分别给同一角色定出不同音色。

音效生成后必须实际试听，确认压低到口播底下仍可辨认、不会遮字或抢戏；听不出声源或不能说明为何放在该处时，重写提示词并重做。没有配音或视频不得称已试听或完成成片；本 Skill 不自动发布或调用付费服务。

字幕必须从当前版本最终纯口播稿生成简体中文字幕，保留中文标点；ASR 只用于词级时间对齐、漏字/合并句审计，不能提供字幕正文。音频或口播稿一旦更换，旧 SRT 视为失效，必须随新时间表重建。

导出前必须检查：字幕文本与最终稿逐句一致；语言为简体中文且标点存在；最后一条字幕时间不早于实际口播结束且不越过音频总时长；视频里确实有可见字幕轨，或已生成烧录字幕预览。至少抽查开头、中段和结尾画面，并在字幕审计 JSON 中记录稿件哈希、时间轴来源、字幕条数和视频时长。

声音规划与生成顺序：从当前已定稿件规划音效，重生成句子 ID 后人工转录采用项到 `production/sound_cues.yaml`，并另交付全文带音效锚点、声源、作用和估算落点的 `audio_script_vN.md`；干净口播单独放入 `voiceover.txt`。不因声音规划重开已确认的编辑意见，也不擅自改稿。`./run.sh sound cues <episode>` 只初始化或迁移清单，不会提取稿件标记；完成转录后再运行 `sound check`、`sound estimate`。汇总角色映射并锁定共享音色表后，分别生成纯口播和音效；用户确认费用后才调用付费模型。最后 `sound assemble` → `sound mix` → `sound check`，导出最终“口播＋音效”时间表并供用户试听。用户接受音频后才能进入分镜；画面分段和字幕只能使用最终时间表，不能按纯口播时长猜。默认不自动调用付费服务；实际生成层可使用 `tools/doubao_long_tts.py` 和 `tools/doubao_audio_gen.py`，而 `bookflow/sound.py` 负责结构检查、估算和本地处理。

## 音频版本、标题卡与导出

**音频版本与视频时间轴必须绑定**：一旦重新混音或压缩音效停顿，旧版 `timing_actual.json`、SRT、分镜时间和视频模板全部失效。视频制作必须读取该音频版本随附的最终时间表，重新切分镜头、重新生成字幕并以成品音频校验总时长；禁止用旧版时间表配新音频，或只替换音频文件名而保留旧切点。交付前用 `ffprobe` 对比视频、音频、字幕末端和最后一个镜头的时间，发现任一版本号或时长不一致就退回重做。

系列视频标题卡的默认模式是 `overlay_on_original_plot_frame`：在系列声音标识段的已有停顿中，直接叠加到原本的剧情画面上，采用“第 N 集—细分隔线—两行集名”的居中层级。标题文字必须来自分集计划或本集 package，样式读取项目 `production/video_style_baseline_v1.yaml`；不得延长音频、重复字幕或另插黑底静帧。

独立 `insert_segment` 只允许用于已经完成的成片补救，且必须记录原因、源视频版本、插入点和人工复核结果；它不是新集的默认制作方法。每个有分集标题的 package 必须通过标题卡前置检查：集数、集名、声音 cue、时间范围、模式和音频版本齐全，否则阻断导出。

## 视觉规则的唯一来源

人物身份、指代消解、叙事时态、8–15 秒切片、每切片独立剧情图、跨集隔离、开场节奏和画面唯一性，统一以 `visual-development` Skill 与项目分镜审计为准。本 Skill 只负责打包和交付，不再复制另一套视觉规则。

打包前必须确认当前定稿 Draft 的哈希、接受的音频版本、最终时间表、字幕审计、分镜/素材审计和标题卡清单指向同一版本。所有机器检查都只是审计结果；`preview_awaiting_human`、试听接受和 AV1/G4 仍必须保持真实人工闸门，不能由脚本代填批准。

连续无口播留白仍需检查：系列片头或关键揭示可以短暂让旁白停下，但不能把多个音效的前后等待直接累加成观众以为“卡住”的长空洞；无明确叙事理由时不超过 8 秒，音效链前后等待通常压到 0.5–1 秒。优先缩短 `pre_pad`/`post_pad` 或合并音效链，不凭空添加旁白。
