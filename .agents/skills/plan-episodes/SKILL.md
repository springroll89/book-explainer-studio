# plan-episodes

读取 [分集与深度](../../../docs/WORKFLOW.md#分集与深度)、项目配置、简报与覆盖结论。

1. 剧情类先按 [剧情文字总纲](../../../style/narrative_charter.md) 梳理原作场景推进、冲突升级与揭示顺序，在自然叙事节点划分集数，再提炼每集牵引问题和带 `id/layer/core/text/evidence` 的 takeaways，分配节拍与字数。takeaways 写读者对处境、选择代价和叙事细节的具体理解，不要求人生教训。论述型作品仍先梳理核心问题与论证，再配置内容。
2. 明确 reveal / withhold、线索埋收和跨集回顾；不讲的章节记入 skipped 并说明理由。
3. 保存 `plan/episodes.yaml`，运行 `./run.sh check-plan <项目路径>` 并修复确定性错误。按 `next` 提交方案确认；用户已明确授权全季文案先行时，可先完成文字初稿和编辑包，保留真实确认状态，不把文字授权延伸到媒体制作。

核心收获必须能由原文或已核实外部来源支撑。个人延伸比例不证明深度；已有明确批准的同版计划无需重复请求确认。

分集计划完成后运行 `./run.sh next <project>`；方案确认绑定实际简报、人物表与计划。改计划后检查受影响文案，不能只刷新指纹消除影响。
