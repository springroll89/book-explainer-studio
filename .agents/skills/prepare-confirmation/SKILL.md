# prepare-confirmation

1. 先运行 `./run.sh next <项目>`，确定当前需要的确认类型、集号和阻断项；不为提前确认而绕过流程。文案确认前，用户认可的版本须先用 `./run.sh final freeze <项目> --eps …` 冻结为 final.md（默认取各集最新草稿；向用户列出每集取的是哪一版，冻结不等于拍板）。旧流程已做完的集，先用 `adopt-legacy` 收编成品（混音、字幕、分镜、视频），再请用户对该成品拍板。
2. 读取确认记录所绑定的当前交付物，列出确切文件、版本/哈希、预览方式与机器检查结果；缺文件、状态过期或依赖失效时，先报告缺口，不请求批准。
3. 按[确认点清单](references/review-checklists.md)说明用户要看/听什么、主要风险和未解决问题。区分机器检查、代理判断与尚未完成人工试听/观看。
4. 仅提交本次确认范围，不捆绑无关文件或目录；不能把审阅报告、历史材料或状态文件冒充交付物。
5. 不代填、模拟、执行批准命令或创建批准记录。批准操作由用户本人按当前生效的项目规则完成；未看到有效记录前只报告 awaiting_human。

任何修改都要先反映到新版本，再重新检查确认绑定和受影响依赖。按方案、文案、样片、成片四项清单整理材料；`next` 的“改动待过目”在下次人工确认时一起展示，不另设小改关卡。
