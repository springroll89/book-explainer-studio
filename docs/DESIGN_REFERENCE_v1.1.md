## 0. 一页总览

**要做的事：** 给一本书或一篇文章，产出 10-15 分钟一集的短视频精讲口播稿，长书做成多集。稿子要读懂原著、讲出深度、按题材讲、像真人说话、只听声音也能懂、节奏抓人。

**核心思路：** 你是主编，编码代理是执行统筹，文件系统是记忆，脚本是质检员，几个互相独立的子代理是审稿团。人在关键节点拍板，人的意见沉淀成规则。

```
            ⓪ 风格校准（首次）
                  │
原文 ─▶ ① 入库 ─▶ ② 拆书+查漏 ─▶ ③ 分集 ─▶ ④ 写稿 ─▶ ⑤ 审校循环 ─▶ ⑥ 入账 ─▶ ⑦ 打包 ─▶ 配音/剪辑
       切章编号    读懂、补漏      切集+深度    读账本     脚本+三方审     记录定稿     交付包
                      │G1            │G2                   +钩子兑现       实际讲了什么
                      ▼              ▼                     │G3/G4
                    人工确认       人工确认                 人工念稿
                                                            │
                               ⑧ 沉淀：反馈 → 规则/人设/样本 ◀┘
```

**交付物：** 每集一个 `deliver/` 目录，内含纯配音稿、带时间码的画面清单、质检摘要、标题与封面文案、字幕重点词、简介标签、BGM 情绪曲线、配音提示。

## 1. 设计目标与约束

### 1.1 目标

| 目标 | 具体要求 | 对应手段 |
|---|---|---|
| 准确 | 不编情节、不错引原文、不歪曲作者意图 | 段落编号、引用核对、事实核查、延伸段落标注 |
| 不漏 | 重要人物、物件、伏笔、作者自述不被遗漏 | 覆盖审计脚本 + 审计代理 |
| 有深度 | 听完不只知道情节 | 四层深度、每集 takeaways、listener 收获对照 |
| 按题材讲 | 悬疑引人入胜、科普深入浅出、情感共情 | 题材规范（含深度配比），每集可指定讲法 |
| 口语化 | 只听声音也能懂 | 口语规则、听觉障碍检测、listener |
| 去 AI 腔 | 看不出是 AI 写的 | 禁用词表、人设、样本、风格基准、去 AI 腔编辑 |
| 节奏快 | 开场抓人，持续有钩子，且钩子是真的 | 钩子标记 + 间隔检查 + 兑现核对 |
| 系列连贯 | 集与集衔接、剧透可控、不重复 | 分集计划 + 以定稿为准的系列账本 |
| 越用越好 | 人的意见能沉淀 | 风格校准、反馈学习、规则文件版本化 |

### 1.2 约束

1. **上下文有限。** 一本二三十万字的书放不进一次对话，硬塞也会读了后面忘了前面。
2. **模型会自信地出错。** 尤其是对名著的印象式记忆，细节和原话常常对不上。
3. **风格会漂。** 同一个提示词，写到第五集时语气可能已经变了。
4. **写的人看不出自己的毛病。** 同一上下文里的自查效果有限。
5. **脚本只能查硬指标。** 字数、句长、词表可以量化；好不好听、有没有深度、钩子是不是真钩子，脚本判断不了，而且模型可能学会“贴标记应付检查”。
6. **核对只能发现写错，发现不了漏掉。** 笔记一开始漏了的线索，后面所有环节都看不到。
7. **计划不等于实际。** 写稿和修订都会偏离计划，后续集数不能按计划推断观众已知什么。
8. **AI 替代不了出声念一遍。**
9. **版权。** 原文不能大段搬进稿子，也不应进公开仓库。

## 2. 核心设计原则

1. **确定的事交给脚本，判断的事交给模型和人。** 脚本零误差、零成本、每次都跑；但脚本通过不是完成标准。
2. **文件就是记忆。** 每个阶段的产出都落成文件，后面只读需要的文件，不依赖对话历史。
3. **写审分离。** 写稿在主线程，审稿交给干净上下文里的子代理，三个审稿角色互相看不到对方结论。
4. **先理解，后表达。** 拆书阶段只管读懂和查漏，不写一个口播字。
5. **标记必须可验证。** 稿件里的自我声明（钩子、延伸），要有独立的来源去核对，而不是只数数量。
6. **连续性以定稿为准。** “观众已经知道什么”只从已确认定稿的账本里取。
7. **人在关键处拍板。** 拆书、分集、第一集定风格、每集念稿。
8. **规则可积累。** 词表、人设、题材规范、样本、风格基准都是文件。
9. **工具无关。** 规则在 AGENTS.md，角色在 roles/，技能用开放的 SKILL.md 格式，脚本是普通 Python。

## 3. 什么是“好精讲”

v1.0 把“怎么讲得好听”定义得很细，“讲到多深”却没定义。结果是系统能稳定产出流畅的剧情复述，但未必有价值。v1.1 把深度拆成可以规划、可以检查的东西。

### 3.1 四层深度

| 层 | 回答什么 | 悬疑小说里的例子 | 社科书里的例子 |
|---|---|---|---|
| 1 发生了什么 | 情节或观点本身 | 周明报警，王福说自己早睡了 | 作者认为习惯比意志力重要 |
| 2 为什么 | 人物动机、观点依据 | 王福说谎，是为了守住陈家的秘密 | 作者引用了哪些研究，逻辑是什么 |
| 3 作者怎么写的 | 叙事安排、伏笔设计、论证策略 | 作者让王福穿着睡衣出场，先骗取读者的信任 | 作者为什么先讲失败案例 |
| 4 怎么看 | 局限、争议、和今天的关系 | “忠仆”形象今天看有什么可商榷之处 | 这些研究后来有没有被质疑，普通人怎么用 |

第 3 层最容易被忽略，也最能区分“精讲”和“剧情速览”。

### 3.2 怎么落到流程里

| 环节 | 做法 |
|---|---|
| 项目配置 | `depth.required_layers`（每集必覆盖）、`series_layers`（系列至少一次）、`commentary_ratio`（评论占比范围）、`goal`（一句话写清这本书精讲的价值） |
| 拆书 | 章节笔记单列“为什么”“作者怎么写的”素材；全书简报有“精讲价值”一节 |
| 分集 | 每集必填 `takeaways`：层次、内容、原文依据。`check_plan.py` 检查层次覆盖和依据是否存在 |
| 写稿 | 提纲里标明每段服务哪条 takeaway；深度要靠细节讲出来，不能念总结 |
| 质检 | `〔延伸〕` 段落的字数占比须在范围内：太低只剩复述，太高喧宾夺主 |
| 审校 | fact-checker 查 takeaway 讲没讲、讲得对不对；listener 独立说出“听完的收获”，与计划对照，只记住情节即判 P1 |
| 交付 | 质检摘要列出本集应带走的认知及依据 |

### 3.3 各题材的建议配比

| 题材 | 第 1 层 | 第 2 层 | 第 3 层 | 第 4 层 | 建议必覆盖 | 评论占比 |
|---|---|---|---|---|---|---|
| 悬疑推理 | 50-60% | 20-25% | 10-15% | 0-10% | 每集 2；系列 3 | 5-20% |
| 科普知识 | 25-35% | 35-45% | 5-10% | 15-20% | 每集 2；系列 4 | 10-30% |
| 情感文学 | 35-45% | 25-35% | 15-25% | 5-10% | 每集 2、3 | 10-30% |
| 社科商业 | 20-25% | 30-40% | 5-15% | 25-35% | 每集 2、4；系列 3 | 15-35% |
| 历史传记 | 40-50% | 25-35% | 5-15% | 10-15% | 每集 2；系列 3、4 | 10-30% |

这些只是起点，真正的标准来自下一节的风格校准。

### 3.4 用真实样稿定标准（风格校准）

规则需要明确的服务对象。第一次使用时，先拿一两份你认可的参考文字稿做画像：

1. **量化画像：** `lint_script.py --stats-only` 输出字数、句长分布（平均、中位、P90）、词表命中密度，不判对错。
2. **人工画像：** 逐段标注后统计深度配比、评论比例、钩子类型与间隔、开场和结尾做法、语气特征、它刻意不做的事。
3. **转成规则：** 调整深度配置、质检阈值、人设、词表和题材节拍，经你确认后生效。
4. **对照验收：** 第一集定稿时，你对照参考稿评价差距，再跑反馈学习。

画像存在 `style/benchmarks/`，参考稿原件放在 `style/benchmarks/raw/`，不进仓库。

## 4. 为什么交给编码代理，而不是聊天窗口

| 能力 | 聊天窗口 | Claude Code / Codex |
|---|---|---|
| 处理整本书 | 受单次上下文限制 | 分章读写文件，按需装载 |
| 执行质检脚本 | 不能或不方便 | 直接运行，结果反馈给模型自动修 |
| 多角色独立审稿 | 同一上下文，容易“自己夸自己” | 子代理各自独立上下文 |
| 强制执行规则 | 靠模型自觉 | 钩子在每次写文件后自动触发 |
| 系列状态 | 靠对话记忆 | 账本文件 + 定稿指纹 |
| 版本管理 | 靠复制粘贴 | 文件版本号 + git |
| 批量生产 | 手动一集一集来 | 可无头运行（`claude -p`、`codex exec`） |

路线上，先用编码代理的会话能力加本地规则、脚本跑通；风格稳定后，先用无头模式批量；直接调用 API 需要自己重建文件读写和子代理机制，放在更后面考虑。

## 5. 总体架构

### 5.1 分层

| 层 | 作用 | 本方案中的文件 | Claude Code 机制 | Codex 机制 |
|---|---|---|---|---|
| 规则层 | 常驻的总规矩 | `AGENTS.md` | `CLAUDE.md`（用 `@AGENTS.md` 引入） | `AGENTS.md`（原生） |
| 流程层 | 可复用的工作步骤 | `.agents/skills/*/SKILL.md` | Skills（`.claude/skills/` 软链过去） | Skills（`.agents/skills/` 原生） |
| 角色层 | 独立上下文的专职工种 | `roles/*.md` | Subagents（`.claude/agents/*.md` 包装） | Subagents（按官方格式包装） |
| 强制层 | 每次必跑的检查 | `scripts/` + 钩子 | Hooks（`.claude/settings.json`） | 手动或 Hooks（测试阶段） |
| 知识层 | 风格、题材、人设、样本、基准 | `style/`、`config/` | 被技能和角色读取 | 同左 |
| 数据层 | 每本书的原文、产物、账本 | `projects/<slug>/` | 文件读写 | 同左 |

> 各工具的配置格式会更新，落地时以官方文档为准：Claude Code 见 code.claude.com/docs，Codex 见 developers.openai.com/codex。

### 5.2 角色分工

| 角色 | 运行方式 | 做什么 | 能看什么 | 产出 |
|---|---|---|---|---|
| 统筹 + 写稿 | 主会话 | 推进流程、拆书汇总、写稿、汇总审校、修订、入账 | 全部 | 分析、计划、草稿、定稿、账本 |
| chapter-reader | 子代理，按章并行 | 精读一章，写结构化笔记（含第 2、3 层素材） | 单章原文 | `chapter_notes/chNN.md` |
| coverage-auditor | 子代理 | 判断覆盖报告里的候选，抽查、核对作者意图依据 | 分析资料、原文 | `coverage_report.md` 结论 |
| fact-checker | 子代理 | 核实事实、引用、剧透、连续性、takeaways | 原文、分析、计划、账本汇总、草稿 | `review/fact_vN.md` |
| deai-editor | 子代理 | 找机器味、书面腔、人设偏差、跨集重复 | 规则、人设、样本、基准、账本手法、草稿 | `review/deai_vN.md` |
| listener | 子代理 | 扮演没读过书的观众 | **只有带时间码的纯口播** | `review/listener_vN.md` |

listener 被刻意限制为只能看纯口播文本。它看不到 `[钩子]` 标记，也不知道原著和计划，所以它的反应可以用来验证标记和深度目标，而不是被它们带着走。

## 7. 流水线详解

### 7.0 风格校准（calibrate-style）

首次使用或更换风格时执行，见 §3.4。产出风格基准画像，以及经确认后的配置、人设、词表调整。

### 7.1 入库（ingest-book）

**输入：** txt / md 原文；epub、docx、pdf 先用 calibre、pandoc、pdftotext 转成 txt。
**输出：** `source/chunks/chNN.md`、`source/index.json`。

关键设计是**全书唯一的段落编号**：每个段落一行，前缀 `[p00001]`。章节笔记、线索表、分集计划、takeaways、稿件引用、事实核查、账本都用这个编号指向原文。

`ingest.py` 自动识别编码（UTF-8、GB18030、Big5）和分段方式；按“第X章 / 第X回 / Chapter / 序章 / 楔子 / 后记 / Markdown 标题”等切章，识别不到时按约 6000 字切块；首章之前的书名、署名等短内容自动跳过并提示。

**人工检查：** 分章是否合理，是否混入目录、版权页、广告；扫描版 OCR 可能有错字。

### 7.2 拆书与查漏（analyze-book）

**目的：** 读懂，并确认没有漏。这一步不写口播文字。

**第一步：逐章精读。** 每章交给 chapter-reader 子代理并行处理，产出不超过 1000 字的结构化笔记：主要内容、人物登场、线索埋收、转折、第 2 层素材（为什么）、第 3 层素材（作者怎么写的）、反复出现的物件或意象、值得引用的原句、不确定之处。每条事实带段落号。

**第二步：汇总。** 主线程只读笔记，写出：

| 文件 | 内容 |
|---|---|
| `book_brief.md` | 一句话讲清这本书、核心命题、作者意图（带依据）、结构与高潮、**精讲价值**（各层素材）、名场面素材、讲述风险 |
| `threads.yaml` | 线索、伏笔、误导、意象、论证环节，每条有埋点和收点 |
| `characters.yaml` | 人物或核心概念、口播时要带的身份、关系、从哪集起才能透露 |
| `misreadings.md` | 容易误解或忽略的点 |

**第三步：覆盖审计。** 事实核查只能发现写错的，这一步专门找漏掉的。

`coverage_audit.py` 做确定性检查：
- 每章是否有笔记，笔记是否引用了本章段落
- 线索的段落号是否存在；埋了没收、且没声明 `payoff: none` 的线索
- 没有任何线索落在其中的章节
- 序、前言、后记等作者自述章节是否被全书简报引用
- 原文高频词（人名、地名、反复出现的物件和说法）在分析资料里一次都没出现的，列为候选。装了 jieba 用分词，否则用 n-gram 统计，并合并错位重叠的片段

然后 coverage-auditor 子代理逐条判断候选（去原文看上下文），抽查无线索章节，列出作者自己强调但简报没提到的内容，检查深度素材够不够。对名著，它可以列出“通常被认为重要的点”，但只作为去原文核实的问题清单。主线程按建议补充，重跑脚本直到没有 ERROR。

在测试中，一份故意漏掉“旧怀表”的分析资料，审计报告列出了“旧怀表（5 次，跨 4 章）”，还顺带列出了“两点十七分”（报警时间与怀表停住的时间一致，是一条真实线索）；同时报出了后记缺笔记、后记未被简报引用、开关灯的伏笔埋了没收。

**闸门 G1：** 核心命题、作者意图、主线索、审计补了什么。

### 7.3 分集（plan-episodes）

**字数换算：** 单集口播字数 = 分钟数 × 语速（默认 240 字/分钟，配音后校准），10-15 分钟约 2400-3600 字。

**切分原则：**
- 按叙事弧或论证单元切，每集自带起承转合
- 一集口播大约覆盖原文 1.5-4 万字
- 每集写明 `core_question`（让人听完的那个问题）和 `takeaways`（听完带走什么）
- 先定 takeaways，再倒推要讲哪些情节
- 每集写明 `reveal` / `withhold`
- 多集时每集有 `cliffhanger`，第 2 集起有 `recap`
- 不讲的章节写进 `skipped` 并说明理由
- 每集可以有自己的 `genre_mode`

**`check_plan.py` 检查：** 必填字段；takeaways 格式、层次覆盖（每集、系列）、依据段落存在；字数预算在时长范围内；题材规范文件存在；high 级线索有埋有收且顺序正确；某集揭示的内容没有出现在后面某集的隐瞒清单里；每章要么被覆盖，要么写进 skipped。

**闸门 G2：** 集数、每集核心问题与 takeaways、剧透边界、结尾钩子。

### 7.4 写稿（draft-episode）

**前置：** 运行 `ledger.py context <集号>`，得到前面各集定稿实际讲过的内容。前面任何一集未入账或账本过期，就停下，不绕过。

**上下文装载顺序：**
1. 项目配置（尤其 `depth.goal`）与全局默认
2. 本集计划条目（核心问题、takeaways、剧透边界）
3. 账本汇总：已揭示信息、观众已知身份、已埋未收线索、上集留下的问题、前情回顾要点、最近用过的手法、计划偏差
4. 全书简报；相关的线索和人物条目
5. 本集章节笔记和原文
6. 口语规则、题材规范、人设
7. 1-2 篇样本，只找语感

**先提纲后正文。** 提纲写在 HTML 注释里：每段讲什么、用哪些段落、预计字数、服务哪条 takeaway、属于第几层、钩子放哪。

**写作要点：** 第一句就是钩子；前情回顾只用账本内容；原文引用逐字照抄并标出处；评论单独成段并以 `〔延伸〕` 开头；takeaways 要讲出来，但不要念出来；`[钩子]` 只标真钩子。

**版本不覆盖。** 每次保存新建 `draft_vN.md`。

### 7.5 审校循环（review-episode）

```
draft_vN
   │
   ├─ 脚本：lint_script + verify_quotes（ERROR 必须清零）
   │
   ├─ 并行 ─┬─ fact-checker  → fact_vN.md
   │        ├─ deai-editor   → deai_vN.md
   │        └─ listener      → listener_vN.md（带 yaml：想继续听 / 想划走 / 收获 / 评分）
   │
   ├─ 脚本：hook_alignment（标记 vs 观众反应）→ hooks_vN.json
   ├─ 深度核对：listener 的收获 vs 计划 takeaways
   │
   ├─ 主线程汇总 → summary_vN.md（合并、分级、取舍、兑现率与评分趋势、样本候选）
   │
   └─ 针对性修订 → draft_v(N+1) ──▶ 回到顶部
```

**问题分级：**
- P0：事实错误、引文不符、剧透、歪曲作者、与前面定稿矛盾、takeaway 讲错、一听就是 AI、念不顺
- P1：容易误解、延伸未标注、takeaway 没讲到、观众只记住情节、钩子兑现率不达标、钩子没接住、明显套路
- P2：可以更好

**意见冲突时的优先级：** 事实 > 听得懂 > 有深度 > 抓人 > 文字漂亮。

**结束条件：** 无 P0、P1 不超过 3 条、钩子兑现率达标；或达到最大轮数（默认 3），剩余问题交给人。

**只做针对性修订。** 整篇重写会把修好的地方改坏，循环难以收敛。假钩子要么真正写出悬念，要么去掉标记，不许只挪标记位置。

**通过后：** 复制为 `final.md` 并加 `status: final`，再跑一遍脚本。
- **G3（第一集）：** 你读稿，意见写进 `feedback.md`，先跑 learn-feedback 再写第二集
- **G4（每集）：** 你出声念一遍并确认。确认后才能入账

### 7.6 入账（update-ledger）

**这是 v1.1 新增的环节。** 系列账本 `series_ledger.yaml` 是“观众已经知道什么”的唯一依据。

**什么时候写：** 只在 G4 确认之后，只根据 `final.md` 写。计划里有但定稿没讲的不写；草稿里讲过但修订删掉的也不会进来。

**写什么：** 本集实际揭示的信息（带依据和时间点）、实际埋下和回收的线索、观众已知的人物身份、留给观众的问题、实际讲出的深度内容、下集前情回顾要点、与计划的偏差、用过的开场结尾和口头禅。

**怎么保证跟随定稿：**
1. 内容写好后运行 `ledger.py stamp`，记录定稿指纹（文件哈希）。没有 `status: final` 或缺字段不能盖章
2. 已入账的定稿被修改时，Claude Code 的钩子会自动把条目标为过期，并列出已经开始写的后续集数；其他环境用 `ledger.py mark-stale` 手动标记
3. 过期后必须重新过 G4、重新入账，并复核受影响的集数
4. `ledger.py context` 在任何前序条目缺失、过期或指纹不符时拒绝输出，写稿随之停止
5. 实际偏离计划且影响后续集数时，回改计划并重跑 `check_plan.py`

### 7.7 打包（package-episode）

先确认本集已入账。然后 `export_episode.py` 生成：
- `voiceover.txt`：去掉所有标记的纯配音稿
- `shotlist.md`：按估算时间码排列的画面、BGM、音效
- `qa_summary.md`：定稿指纹、账本状态、硬指标、覆盖章节与引用段落、本集应带走的认知及依据、审校轮数、未清零的 warn；“剩余已知问题”由技能根据最后一轮汇总补写

模型再生成 `package.md`：五种风格的标题、三组封面大字、字幕重点词、简介、标签、BGM 情绪曲线、互动问题、配音提示。标题同样受去 AI 腔规则和剧透边界约束。

### 7.8 沉淀（learn-feedback）

输入：`feedback.md` 的意见；人手改后的 `final_human.md` 与 `final.md` 的差异；审校汇总里的样本候选（观众被吸引但没标钩子的段落）；反复出现的假钩子写法。

| 反馈类型 | 沉淀到 |
|---|---|
| 某个词句别扭 | `style/banned.yaml` |
| 书面词 | `banned.yaml` 的 `written_to_spoken` |
| 语气、口头禅、态度 | 人设文件 |
| 结构、节奏、反复出现的假钩子写法 | `style/genres/*.md` |
| 深度不够、评论太多或太少 | `project.yaml` 的 `depth`，或题材规范的深度配比 |
| 阈值（句长、钩子间隔、语速） | `config/defaults.yaml` 或 `project.yaml` |
| 写得特别好的段落、自然钩子 | `style/samples/` |
| 只针对这本书 | `project.yaml` 的 `notes` |

改规则前必须经你确认；改完拿最近一集重跑质检，确认没有误伤。配音后用实际音频时长校准语速。

## 8. 准确性保障体系

两类错误分开防：**写错**（说了原著没有的）和**漏掉**（原著有、分析里没有）。

| 时点 | 手段 | 防什么 |
|---|---|---|
| 事前 | 原文入库并编号；“原文是唯一依据” | 凭印象写 |
| 事前 | 笔记每条事实带段落号；作者意图须注明依据 | 流行解读冒充作者原意 |
| 事前 | 笔记单列“反复出现的物件/意象”，宁多勿漏 | 细节遗漏 |
| 事前 | **覆盖审计**：高频词对照、章节与线索覆盖、作者自述引用 | 漏读 |
| 事前 | `project.yaml` 记录版本/译者 | 译本措辞不同 |
| 事前 | takeaways 必须带依据，`check_plan.py` 校验段落存在 | 深度内容无据 |
| 事中 | 引用写成 `〔引 p00123〕「…」`；评论放进 `〔延伸〕` 段落 | 引文无法追溯；把自己的理解说成作者的 |
| 事中 | 写稿前从账本汇总观众已知 | 前后矛盾、把没讲过的当讲过 |
| 事中 | 不确定处写 TODO 并上报 | 编造 |
| 事后 | `verify_quotes.py` 逐字比对，编号标错时给出正确位置 | 错引、改引 |
| 事后 | fact-checker 核对情节、关系、时间、数字、剧透、连续性、takeaways | 事实错误 |
| 最后 | 人工闸门 | 以上都漏掉的 |

## 9. 口语化与去 AI 腔保障体系

四道关：

1. **生成时就写对。** 口语规则告诉模型不要什么；人设告诉它谁在说；样本和风格基准告诉它要什么。样本最管用。
2. **脚本硬查。** `banned.yaml` + `lint_script.py`。
3. **两个代理软查。** deai-editor 找脚本查不出的机器味（结构模板化、每段结尾都升华、假口语、替观众下结论、句式反复、人设走形、与前几集手法重复）并给逐句改写；listener 从观众角度找听不懂和想划走的地方。
4. **人出声念。** 不可替代。

### 9.1 禁用词表

每条规则有级别、上限、作用范围：

```yaml
- id: not_but
  level: warn
  max: 1                  # 一集最多一次
  desc: “不是……而是……”类对照句
  patterns:
    - '不是[^。！？]{1,20}而是'
    - '不仅仅?是[^。！？]{1,20}(更|也|还)是'

- id: bad_opening
  level: error
  scope: opening          # 只查开头
  window: 120
  patterns: ['大家好', '今天(给大家|我们来|要跟大家)', '你有没有想过']
```

大多数规则是“限次”而非“禁止”：这些词本身没错，问题在密度和位置。全部禁掉，稿子会干巴巴，模型也会换一批新套话顶上。

| 组 | 级别 | 例子 |
|---|---|---|
| 万能连接词 | error | 值得注意的是、不难发现、由此可见、综上所述 |
| 空洞拔高 | error | 深刻揭示、发人深省、在这个……的时代、一场关于……的旅程 |
| 对照套句 | warn，每集 ≤1 | 不是……而是、不仅是……更是、与其说……不如说 |
| 解说口头禅 | warn，每集 ≤2 | 换句话说、本质上、说到底、某种程度上 |
| 网络热词 | warn，每集 ≤1 | 细思极恐、破防、天花板、炸裂 |
| 套路开场 | error，前 120 字 | 大家好、今天给大家、你有没有想过 |
| 套路结尾 | warn，后 150 字 | 或许这就是、愿你、让我们 |
| 书面词 | warn，给替换建议 | 因此→所以、然而→可是、倘若→要是 |

### 9.2 “写给耳朵”的量化项

| 检查 | 默认阈值 | 原因 |
|---|---|---|
| 单句长度 | >35 字提示，>55 字判错 | 听众记不住长句开头 |
| 无停顿片段 | >20 字提示 | 配音换不过气 |
| 节奏单调 | 连续 8 句长度变异系数 <0.22 | 句子一样长，听着催眠 |
| 排比 | 连续 3 句开头相同 | 模板化三连 |
| 括号、破折号、分号、斜杠 | 出现即提示 | 听不见 |
| 英文缩写、长数字、百分比 | 出现即提示 | 要写成念法 |
| 评论占比 | 按 `depth.commentary_ratio` | 只剩复述，或喧宾夺主 |

**这些指标只能说明“不违规”，不能说明“有真人语感”。** 语感靠样本、审校代理和人耳朵。

## 10. 题材适配

每种题材一份规范文件：核心目标、深度配比（§3.3）、结构节拍（按时长占比）、钩子手法、要做、不要做、审校清单。

| 题材 | 核心目标 | 节拍骨架 |
|---|---|---|
| 悬疑推理 | 管理信息差 | 冷开场 → 人物处境 → 埋线索 → 误导升级 → 揭示 → 悬置 |
| 科普知识 | 深入浅出 | 反常识开场 → 生活类比 → 概念台阶 → 边界反例 → 回到生活 → 一句话带走 |
| 情感文学 | 共情 | 具体场景 → 人物处境 → 细节放大 → 选择与代价 → 克制收束 |
| 社科商业 | 带走一个工具 | 反直觉结论 → 案例 → 论证链 → 怎么用 → 局限争议 → 带走 |
| 历史传记 | 人与选择 | 命运转折点 → 倒回去 → 时代背景 → 抉择 → 代价 → 回望 |

新增题材时照同样结构加文件，并在 `new_project.py` 的题材列表里登记。

## 11. 节奏与钩子：从标记到兑现

### 11.1 标记与间隔

1. 写稿时在钩子句末尾加 `[钩子]`
2. 脚本按“钩子前累计口播字数 ÷ 语速”算出时间点
3. 检查：第一个钩子在 30 秒内（error）；相邻间隔不超过 90 秒，含最后一个钩子到结尾（warn）；没有钩子（error）

### 11.2 兑现核对

只数标记有漏洞：模型可能在平淡的句子后面也贴一个 `[钩子]`，间隔检查照样通过。所以标记只是“待验证的承诺”。

1. listener 拿到的是**带时间码、没有任何标记**的纯口播（`export_episode.py --voice-only --timecodes`），时间码和钩子时间点用同一语速计算
2. listener 在报告的 yaml 块里独立写出“想继续听”和“想划走”的时刻及原因
3. `hook_alignment.py` 按距离全局配对（容差默认 ±10 秒，每个钩子、每个反应只用一次），输出：

| 结果 | 含义 | 处理 |
|---|---|---|
| 兑现 | 标记附近观众确实被吸引 | 保留 |
| 疑似假钩子 | 标了，观众没反应 | 写出真正的悬念，或去掉标记；不许只挪位置 |
| 没接住 | 钩子后 20 秒内观众想划走（划走归给之前最近的钩子） | 检查钩子后那段是不是泄了气 |
| 自然钩子 | 没标，观众被吸引 | 样本候选 |

兑现率（兑现数 ÷ 标记数）低于 60% 列为 P1。

测试样例的输出：
```
标记 5 处，兑现 3 处，兑现率 60%（要求 ≥60%，容差 ±10 秒）
[疑似假钩子] 0:14 标了钩子，观众没有反应
[疑似假钩子] 0:25 标了钩子，观众没有反应
[没接住]     0:25 的钩子后，0:28 观众想划走：管家干了二十年这句有点平
[自然钩子]   0:46 没标记但观众被吸引：九点就睡的人鞋为什么湿，这个反问很有劲（样本候选）
```

**局限：** listener 仍然是模型，不是真观众。它的判断比标记可信，但最终仍以人工试听和平台完播数据为准（§20）。

**钩子类型备忘：** 设问、卖关子、预告回收、反转、反差、时间压力、让观众代入做选择、数字对比、“你记住这个”。

## 12. 长书、多集与连续性

### 12.1 上下文管理

1. **分层摘要：** 原文 → 章节笔记（每章 ≤1000 字）→ 全书简报。写某一集只装载简报、本集笔记和本集原文。
2. **子代理隔离：** 精读、审计、审校都在子代理里，主线程只收到结论和文件路径。
3. **结构化索引：** 线索表、人物表、账本是 YAML，按编号精确取用。
4. **会话可中断：** 所有状态在文件里。建议入库+拆书一个会话，分集一个会话，每集写稿到入账一个会话。

### 12.2 三种“系列信息”的分工

| 文件 | 性质 | 回答的问题 | 谁写、何时写 |
|---|---|---|---|
| `threads.yaml`、`characters.yaml` | 关于原著 | 书里有什么线索、人物是谁 | 拆书阶段 |
| `plan/episodes.yaml` | 关于意图 | 每集打算讲什么、揭示什么、隐瞒什么 | 分集阶段，偏差影响后续时回改 |
| `series_ledger.yaml` | 关于事实 | 观众实际已经知道什么 | 每集 G4 确认后，从定稿生成 |

写稿和核查时，“观众已知”只看账本。计划和账本不一致时，以账本为准，并决定是否回改计划。

### 12.3 账本的生命周期

```
final.md 定稿 ──G4 确认──▶ update-ledger 写条目 ──▶ ledger.py stamp（记录指纹）──▶ ok
     │                                                                       │
     └─ 修改已入账定稿 ─▶ 钩子自动 mark-stale ─▶ 列出受影响的后续集数 ─────────┘
                           │
                           └─▶ ledger.py context 拒绝输出 ─▶ 后续写稿暂停，直到重新确认、重新入账
```

## 13. 脚本说明

依赖：Python 3.9+，`pip install pyyaml`；可选 `pip install jieba`。所有命令在仓库根目录执行。

| 脚本 | 用途 | 退出码 |
|---|---|---|
| `new_project.py <slug> --title --author --genre` | 从模板新建书目 | |
| `ingest.py <项目> <原文...>` | 分章、段落编号、索引 | |
| `coverage_audit.py <项目> [--top N]` | 拆书查漏，写 `coverage_report.md` | 有 error 为 1 |
| `check_plan.py <项目>` | 分集计划校验 | 有 error 为 1 |
| `lint_script.py <稿件> [--json]` | 口播稿质检 | 有 error 为 1 |
| `lint_script.py <参考稿> --stats-only` | 风格画像，不判对错 | 0 |
| `verify_quotes.py <稿件>` | 引用逐字核对 | 有问题为 1 |
| `export_episode.py <稿件> --voice-only [--timecodes]` | 打印纯口播（可带时间码） | |
| `hook_alignment.py <稿件> <listener报告> [--json]` | 钩子兑现核对 | 0（信号） |
| `ledger.py check <项目>` | 账本与定稿一致性 | 有问题为 1 |
| `ledger.py stamp <项目> <集号>` | 入账盖章 | 条件不满足为 1 |
| `ledger.py mark-stale <项目> <集号> --reason` | 标记过期，列出受影响集数 | |
| `ledger.py context <项目> <集号>` | 汇总前序各集，供写稿 | 前序不完整为 1 |
| `export_episode.py <定稿>` | 导出配音稿、画面清单、质检摘要 | |
| `.claude/hooks/check_on_write.py` | 写稿后自动质检；定稿改动时让账本过期 | 有问题为 2 |

**配置合并：** 先读 `config/defaults.yaml`，再由稿件所在目录向上找到 `project.yaml` 覆盖。

**钩子：** Claude Code 每次写入或编辑文件后把工具参数传给钩子脚本。脚本只处理 `episodes/` 下的 `draft_*.md` 和 `final.md`；有 ERROR，或已入账的定稿被改动，就以退出码 2 结束，报告交给模型处理。账本只在第一次被改动时拦截并标为过期，之后的编辑不会重复拦截。

**关于 warn：** 是信号不是命令，只有 error 会阻断流程。

**测试记录（v1.1）：** 用自写的测试文本跑通了全流程。一份 AI 腔很重的稿子被查出 4 个 error、10 个 warn；两处错误引用都被发现，其中一处给出了正确编号；有问题的分集计划被查出 9 个 error（缺层次、字数越界、题材文件不存在、依据段落不存在、系列缺第 3 层、高优先级线索未安排、章节未覆盖），另测出了剧透冲突；账本在前序未入账时拒绝汇总，定稿被改动后自动过期并提示受影响的第 2 集。

## 14. 人工闸门与协作方式

| 闸门 | 时机 | 你要看什么 | 大约耗时 |
|---|---|---|---|
| 校准确认 | 风格校准后 | 画像是否抓住你喜欢的点；配置调整是否认可 | 15-30 分钟（一次性） |
| 分章确认 | 入库后 | 章节数、有没有混入杂项 | 1 分钟 |
| G1 | 拆书后 | 核心命题、作者意图、主线索、查漏补了什么 | 5-10 分钟 |
| G2 | 分集后 | 集数、核心问题、takeaways、剧透边界 | 5-10 分钟 |
| G3 | 第一集定稿 | 风格、人设、节奏、深度，对照参考稿逐句挑刺 | 20-30 分钟 |
| G4 | 每集定稿 | 出声念一遍；确认后才入账 | 约一集时长 |

风格稳定后，可以把 G1、G2 改成 `auto`；G4 建议一直保留，因为它同时是账本的入口。

**反馈怎么写最有效：** 哪里 + 为什么不舒服 + 希望怎样。比如：“第 12 行‘说白了’太像模板了，老哥不会这么说，换成‘直说吧’”；“这集只讲了情节，王福为什么撒谎完全没展开”。

## 18. 成本与效率

**消耗大头：** 拆书（全书过一遍 + 覆盖审计）和审校循环（每轮三个代理）。

**控制办法：**
- 拆书只做一次，产物反复用
- chapter-reader 用较便宜的模型；覆盖审计先由脚本筛出候选，代理只判断候选
- 审校轮数上限默认 3；经常到上限说明写稿阶段的规则或样本不够，应该回头补
- 风格稳定后，deai-editor 可只在第一轮跑；listener 每轮都跑（它承担钩子兑现和深度核对）
- 每集单独开会话

**人工时间的主要去处：** 风格校准、G3、G4。这三项别省。

## 19. 风险与对策

| 风险 | 表现 | 对策 |
|---|---|---|
| 幻觉 | 编情节、编原话、编作者观点 | 段落编号、引用脚本、事实核查、作者意图须有依据、TODO |
| 漏读 | 重要线索从笔记起就缺失 | 笔记单列反复出现的物件；覆盖审计；名著要点只作核实清单 |
| 只有复述 | 流畅但没价值 | 四层深度、takeaways 必填、评论占比、listener 收获对照 |
| 标记应付 | 钩子、延伸标记名不副实 | listener 盲听 + 兑现核对；fact-checker 检查延伸段落；规则明确禁止 |
| 脚本迷信 | 全过了但不好听 | AGENTS.md 明确脚本通过不是完成标准；G3、G4 |
| 连续性错误 | 把没讲过的当讲过；前后矛盾 | 账本只来自已确认定稿；指纹校验；改动自动过期；写稿前强制汇总 |
| 计划漂移 | 实际偏离计划，后续集数不知道 | 账本记录偏差；影响后续时回改计划并重跑校验 |
| 剧透 | 前几集说漏 | reveal / withhold；check_plan 冲突检测；人物表 spoiler_from；核查；标题受限 |
| 译本差异 | 引用对不上 | 记录版本；以入库原文为准 |
| 风格漂移 | 越写越像 AI、人设走形、跨集重复 | 每集重载人设和样本；账本记录用过的手法；deai-editor 检查 |
| 规则过拟合 | 为过质检把稿子改僵 | warn 不阻断；新规则需确认并回归测试；阈值不直接照抄参考稿 |
| 同义替换 | 禁一批套话，冒出一批新套话 | 找“同一句式反复”；新套话入表；样本引导 |
| listener 失真 | 模型观众和真实观众不一样 | 人工试听；平台完播数据回流校准 |
| 版权 | 大段搬运原文或模仿他人稿件 | 引用上限；原文和参考稿不进 git；样本库只放自己的稿子；参考稿只做画像 |
| 价值与合规 | 敏感内容处理不当 | 简报“讲述风险”；project notes；人工闸门 |
| 工具变更 | 配置格式更新 | 工具相关文件很薄，逻辑在 roles/ 和 scripts/ |

## 20. 后续扩展

- **批量无头生产：** 外层脚本用 `claude -p` 或 `codex exec` 逐集调用“写稿 + 审校”，在闸门处停下通知人。
- **配音对接：** `voiceover.txt` 喂给 TTS；配音提示转成 SSML 停顿和重音。
- **语速自动校准：** 读取音频时长，回写 `speech_rate_cpm`，时间码随之更准。
- **完播数据回流：** 把平台后台的掉人曲线与稿件时间码对齐，和 listener 的“想划走”对比，校准 listener；掉人多的位置作为反面样本。这是让稿子越写越好的最有力信号。
- **系列化：** 固定的开场口令、集数播报、结尾互动模板写进人设；账本已记录用过的手法，可避免重复。
