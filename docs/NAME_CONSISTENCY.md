# 统一译名与资料同步

名称更正是本书的实体资料变更，不能只记成个人风格。人物稳定 ID 不变，德文原名不变，中文显示名可以修订。现有人物表 `analysis/characters.yaml` 就是唯一用名依据，不另建相互竞争的名称表。

## 触发与身份核对

- 用户明确说“把甲改成乙”：核对所属人物 ID、原文名、上下文和适用书目后同步。明确指示已有授权，不重复请求许可。
- Markdown 或 DOCX 差异碰到已知人名：`import-edits` 在 `name_review_candidates` 中列出人物和差异编号。删句、重排也可能碰到人名，因此只提示专项核对，不擅自认定改名。
- 批注、口头说明里的名称要求仍需阅读，不能只看机器候选。人物表未收录的新名字先回原文确认身份。
- 同姓、简称歧义或原名不同：先消歧。不得按读音相似或汉字相近合并两个人。
- 本次用户的“伯恩施泰因 → 伯恩斯坦因”已明确只是举例，因此不修改真实人物表或第一集。

## 一次完整同步

1. **列影响清单**。运行 `./run.sh name-change <书目路径> --entity <人物ID> --name <新口播名> --output <变更单路径>`。清单记录原名、新名、文件位置、出现次数及当前文件摘要。命令只生成清单，具体同步由助手按以下步骤执行。
2. **保留变更前证据**。在本书 `name_changes/<本次编号>/` 保存变更单及将被修改文件的原样副本。执行前再次核对文件摘要；如果用户正在编辑或文件已变化，重新读取并合并，不覆盖人工新修改。
3. **更新人物表**。人物 ID 与 `name_de` 保持不变。修改 `spoken_name` 和必要的 `name_zh`，保存更正依据和旧称映射。简称、全名分别处理；不能推断的全名先人工核对。
4. **同步当前资料**。核查人物关系、逐章笔记、全书简报、线索说明、分集计划、当前集稿、标题、封面文字和制作说明。只更正名称，不改写案情。中文直接引文保留原样并说明现用名；若造成名称检查命中，需调整引用呈现和重新核查，不能用全局忽略掩盖问题。
5. **另存稿件版本并更新入口**。保留 `draft_vN.md` 和用户正在修改的 DOCX，另存新版稿及新版编辑包；将 `status.yaml` 的当前稿件入口更新为新版。人工改稿的原版/改版证据不改写。未完成的审校、旧审校结论均不能自动升级为新稿已通过。
6. **重生成派生文件**。从新版稿重新输出当前口播文件、字幕、阅读页等；受影响的音频、视频、已发布内容列为“待重新生成/待处理”，不能靠改文件名宣称已同步。已入账稿先运行现有 `ledger mark-stale` 标记受影响集数，再重新核对来源、审校和账本依赖。
7. **闭环验收**。运行 `names-check`、新版稿 `lint`、`quotes` 及受影响审校；报告原称→现称、对应人物、修改文件及次数、历史保留范围、仍待重生成的产物。清单内的活动资料无旧称遗漏、受影响输出已更新，才能说同步完成。

## 旧称登记格式

以下只是格式示例，不代表真实人物更名：

```yaml
id: P01
name_de: 原文名称保持不变
name_zh: 当前中文全名
spoken_name: 当前中文简称
name_decision:
  reason: 用户明确指定的用名
  evidence: 本书改稿轮次/批注/会话中的具体说明
aliases_zh:
  - text: 之前的中文简称
    replacement: 当前中文简称
    status: deprecated
  - text: 之前的中文全名
    replacement: 当前中文全名
    status: deprecated
```

再次更名时，所有旧称都直接指向最新用名，避免“甲→乙→丙”的过时链条。旧称如果与另一人物现用名重叠，检查会要求先消歧。新名字含有旧名字时按最长名称匹配，避免反复误报。

## 检查范围与历史追溯

`./run.sh names-check <书目路径>` 扫描当前分析、计划、每集版本号最大的稿件、定稿、制作文案以及当前文字预览/交付文件，输出旧称所在文件、行号和人物 ID。`lint` 会把新稿中已停用的译名当作错误，正式导出沿用此检查。写稿技能、反馈技能和打包技能均已接入名称同步流程。

原文、旧稿、审校记录、反馈差异和编辑基线保持原样。读历史材料时用人物 ID、原文名、`aliases_zh` 对照现用名；旧文件中的旧称是历史证据，不能充当新的用名依据。扫描不验证二进制音视频里的实际读音，也不将“零旧称命中”当作事实或身份正确的证明。

当前 `name-change` 自动列出已知中文口播名与全名的影响；别称、未登记的错字和陌生音译仍由助手根据原文补查。人物表以书目隔离，不把同名修改扩展到其他书。

## 本次实现与验收

名称相关行为可用 `./run.sh names-check projects/my-book` 在本机书目上验证；检查结果不替代人工核对人物身份。

变更文件：

- `bookflow/names.py`：人物身份、旧称映射、影响清单、活动文件检查和名称变动候选。
- `bookflow/__main__.py`：`names-check` 与 `name-change` 命令。
- `bookflow/feedback.py`：导入改稿时提示名称核对，写稿上下文纳入人物表和一致性结果。
- `bookflow/quality.py`：稿件中已停用名称作为错误报告。
- `tests/test_names.py`：冲突、旧称链、前缀重叠、历史保护、影响范围及稿件检查测试。
- `.agents/skills/learn-feedback/SKILL.md`、`.agents/skills/draft-episode/SKILL.md`、`.agents/skills/package-episode/SKILL.md`：同步执行流程和检查入口。
- `docs/NAME_CONSISTENCY.md`、`docs/HUMAN_EDITING.md`、`docs/WORKFLOW.md`、`README.md`：用名依据、同步步骤、版本保护和验收说明。

自动工具负责定位和查漏，助手负责确认实体、执行有证据的同步、处理直接引文和重生成产物；并非未经身份核对就全库替换。
